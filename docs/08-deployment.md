# 8. Deployment & Release Process

This document covers everything about getting a new version of the app
into production.

---

## 8.1 Where the app is hosted

The production deployment lives at:

> [https://bettergovernmentlab.shinyapps.io/snap-qc-shiny/](https://bettergovernmentlab.shinyapps.io/snap-qc-shiny/)

It is hosted on **shinyapps.io** (RStudio/Posit Connect's hosted Shiny
service) under the **`bettergovernmentlab`** account.

A second deployment target also exists for staging / personal use:

> [https://xiao-dataviz.shinyapps.io/snap-qc-shiny/](https://xiao-dataviz.shinyapps.io/snap-qc-shiny/)

Both are configured in the `rsconnect/shinyapps.io/` folder of this repo.

| Folder | Account | App ID | URL |
|---|---|---|---|
| `rsconnect/shinyapps.io/bettergovernmentlab/snap-qc-shiny.dcf` | `bettergovernmentlab` | `16949783` | production |
| `rsconnect/shinyapps.io/xiao-dataviz/snap-qc-shiny.dcf` | `xiao-dataviz` | `16657174` | personal/staging |

The `.dcf` files are auto-managed by `rsconnect::deployApp()` — you
generally should not edit them by hand. They are included in the repo so
that deploying to the same target twice produces an *update*, not a
brand-new app.

---

## 8.2 Prerequisites for deploying

You need:

1. **A shinyapps.io account** with deploy access to the
   `bettergovernmentlab` team. Contact a current Lab admin to be added.
2. **An account token** — get it from the shinyapps.io UI:
   *Account → Tokens → Show* → copy the snippet that begins
   `rsconnect::setAccountInfo(...)`. Run it once per machine.
3. **The `rsconnect` R package** installed (`install.packages("rsconnect")`).
4. **A clean working tree** — the entire app folder is bundled and
   uploaded, so any uncommitted file ends up in the deployment unless
   it is in `ignoredFiles` (see below).

---

## 8.3 Files that get bundled (and files that don't)

`rsconnect::deployApp()` uploads the contents of the directory you point
it at. Files matched by the `ignoredFiles` field of the `.dcf` are
excluded.

Current `bettergovernmentlab/snap-qc-shiny.dcf` (line 13) excludes:

```
.claude/settings.local.json
app_副本.R
requirements/Base Rates tab Sample image.png
requirements/requirements description.png
requirements/Sample image1.png
```

Things you should keep in mind:

- **`data/`** ships in full — every `.RDS` is uploaded. Total payload is
  ~5 MB, well within shinyapps.io limits.
- **`www/`** ships — the two logos are served as static assets.
- **`.git/`, `.Rhistory`, `.Rproj.user/`** are excluded by `rsconnect`'s
  built-in defaults; you do not need to list them.
- **`rsconnect/`** is technically uploaded but ignored by the runtime;
  it is only needed locally so that `deployApp()` can find the existing
  app ID for an in-place update.
- **`docs/`** (this folder) — currently NOT excluded. If you do not want
  documentation in the deployment bundle, add `docs/.*` to `ignoredFiles`
  in the `.dcf`.

## 8.4 The standard release process

Assuming you are pushing a routine update (new data year, bugfix, or
copy change):

```r
# 1. Open the project directory in R.
setwd("path/to/snap-qc-shiny")

# 2. Sanity-check locally first — every tab should render with no errors.
shiny::runApp(launch.browser = TRUE)
# ... click through all five tabs, then close the browser/stop Shiny ...

# 3. Deploy to PRODUCTION (bettergovernmentlab).
rsconnect::deployApp(
  appDir   = ".",
  appName  = "snap-qc-shiny",
  account  = "bettergovernmentlab",
  forceUpdate = TRUE      # update the existing app rather than create new
)
```

`deployApp()` will:

- Bundle the directory (skipping `ignoredFiles`).
- Upload the bundle to shinyapps.io.
- Trigger an R 4.x build that calls `renv::restore()` against the
  package set captured in `manifest.json` (auto-generated by `rsconnect`).
- Restart the running container.

Total time: typically **3–8 minutes** for an update, longer the first
time a year because of dependency installs.

To deploy to the personal/staging target instead:

```r
rsconnect::deployApp(
  appDir   = ".",
  appName  = "snap-qc-shiny",
  account  = "xiao-dataviz",
  forceUpdate = TRUE
)
```

## 8.5 Verifying a release

After `deployApp()` returns successfully:

1. Open
   [https://bettergovernmentlab.shinyapps.io/snap-qc-shiny/](https://bettergovernmentlab.shinyapps.io/snap-qc-shiny/)
   in an incognito window (so you bypass any cached JS/CSS).
2. Click each of the five tabs in turn.
3. Confirm any data changes are visible (e.g., the new year's threshold
   in the threshold tooltip; the new year showing up in the year
   pickers).
4. Open the **shinyapps.io dashboard → Logs** tab and confirm there are
   no `Warning:` or `Error:` lines from the cold start.

If the deployment fails or you see runtime errors that don't reproduce
locally, the logs are your single source of truth. The most common
causes are:

- A new package was added to `library(...)` but not installed via the
  manifest. `rsconnect` should pick this up automatically, but if you
  added a package via `pak::` or `remotes::` and it was not on CRAN at
  the time of the build, it can fail. Make sure all dependencies are on
  CRAN.
- The `.RDS` file you regenerated has a different schema than the app
  expects. The error message will reference a missing column name (e.g.
  `'Case ID' not found`). Rebuild the data with the schema in
  [`03-data-files.md`](03-data-files.md).

## 8.6 Rolling back

shinyapps.io keeps the previous bundle. To roll back without re-deploying:

1. Log into shinyapps.io.
2. Navigate to *Applications → snap-qc-shiny → Settings*.
3. Use the **Versions** tab to redeploy a previous bundle.

To roll back from a clean state on your laptop:

```bash
git log --oneline             # find the last good commit
git checkout <good-sha> -- .   # restore working tree to that commit
```

Then run `rsconnect::deployApp(...)` as in section 8.4. **Do not**
amend or force-push to `main` to "undo" — keep history honest and use
`git revert` if you need a clean rollback commit.

## 8.7 Account & secrets management

There is **no `.env`, no API keys, and no secrets** anywhere in this
codebase. The only credentials involved are:

- **Your shinyapps.io token**, stored locally by `rsconnect` after you
  run `rsconnect::setAccountInfo(...)`. It lives in
  `~/.rsconnect/accounts/<account>/shinyapps.io.dcf` (Linux/macOS) or
  the Windows equivalent. **Never** check this file in.
- **No analytics** is enabled today. The HTML include for Google Analytics
  is commented out at `app.R:158` (`# includeHTML("google-analytics.html")`).
  If you want analytics back, drop the file under the project root and
  uncomment the line.

## 8.8 Release checklist (paste into your PR / changelog)

```
[ ] Local: shiny::runApp() launches without warnings.
[ ] Local: all 5 tabs render with default filters.
[ ] If data updated: threshold_by_year covers all years present in data/.
[ ] If data updated: bind_rows() lists in app.R include the new year.
[ ] If data updated: schema check (column names match docs/03-data-files.md).
[ ] rsconnect::deployApp(account = "bettergovernmentlab") returned OK.
[ ] Production URL loads in incognito.
[ ] All 5 tabs verified on production.
[ ] shinyapps.io logs show no cold-start errors.
[ ] Commit + push the source change so HEAD reflects what's deployed.
```
